# KithCore

**A social-first multiplayer RPG engine for evolving shared worlds.**

[Source](https://github.com/jspjut/kithcore) · [Downloads](https://github.com/jspjut/kithcore/releases) · [Project site](https://jspjut.github.io/kithcore/) · [Issues](https://github.com/jspjut/kithcore/issues)

These are the intended public release destinations; publication is tracked in the [release checklist](docs/OPEN_SOURCE_RELEASE.md).

The initial release was generated by **Codex**, using a mix of **GPT-6.1 Sol** and **GPT-6.1 Astra**, under human direction; see [origin and licensing](PROVENANCE.md).

KithCore is MIT licensed, with an authoritative Node.js server and an included small example game. **Meadow Sample** is a small 3D world with five compact landscape regions, three rest stops, exploration, combat, gathering, three introductory quests, two hub breadcrumbs, multiplayer chat and saved characters. Humans and Harefolk can train as Adventurers or Scholars, and both worlds use the same shared interface.

The shared client includes character creation/customization, equipment and bags, action bars, casting feedback, quest windows, maps, keybindings/settings, parties, friends, chat, bank and post interfaces. Games customize its branding, styles and behavior through world-owned modules; see [client customization](docs/CLIENT_CUSTOMIZATION.md).

**[Emberwild](docs/EXAMPLES.md)** is a separate, larger demo game with a mostly complete starting zone and additional city/region content. It is a starting point for development, not a finished MMO. The base engine works without its files or assets. Both games use the same simulation, movement prediction, inventory, quests and persistence code.

## Play with one command

On Linux or macOS, extract a release download, open a terminal in its folder, and run:

```sh
./start.sh
```

Open **http://localhost:3080** in a desktop browser with WebGL/hardware acceleration. The launcher uses Node.js 22+ if installed; otherwise it downloads a checksum-verified local Node.js 24 runtime. First setup needs internet access. It installs the two production dependencies, which are served locally thereafter. No account provider, CDN or model service is required.

On Windows, install Node.js 22+, then run:

```sh
npm ci --omit=dev
npm start
```

Choose a race, class and character name. Walk with **WASD**, jump with **Space**, and speak to **Guide** with **F** or a nearby right-click. Accept the first quest and visit the blue marker north of camp. Left-click selects a creature; right-click starts auto-attack. Use the numbered action bar for abilities. **B** opens bags, **C** equipment, **P** the spellbook, **J** the journal, **M** the atlas, and **Escape** the game menu. Herbs grow in the western field. Supplier sells bags and tonics, Keeper provides storage, and the mailbox sends letters and items. Right-drag rotates the camera; scrolling changes its distance.

For a second player, open another browser profile/private window. The Node launcher listens on all interfaces by default, so friends on your LAN can visit `http://YOUR_HOST_IP:3080`. Set `HOST=127.0.0.1` for local-only Node play. Browser profiles and server addresses have separate identities. **Game menu → Log out** confirms logout; saves also run every ten seconds. Clearing browser storage loses access to the remembered identity.

## Docker

With Docker and Docker Compose installed:

```sh
docker compose up --build
```

Open **http://localhost:3080**. Docker binds to your own machine by default. To allow LAN connections:

```sh
BIND_ADDRESS=0.0.0.0 docker compose up --build
```

`docker compose down` stops the game while retaining its named save volume. See [deployment, backups and troubleshooting](docs/DEPLOYMENT.md) before upgrading or exposing a server to the internet.

## Choose a world

The engine download includes `worlds/minimal/`. To use another installed pack:

```sh
./start.sh --world emberwild
# Or use an extracted pack anywhere on disk:
npm start -- --world /absolute/path/to/my-world
```

An Emberwild starter download includes the engine, the minimal example and Emberwild, with `default-world.json` selecting Emberwild. Its one-command Node setup is also `./start.sh`. The starter's generated `compose.override.yaml` makes plain `docker compose up --build` select Emberwild too, mounted read-only outside the image. From a source checkout, place the separate Emberwild package at `worlds/emberwild/` and use the command above.

For Emberwild in Docker, use the read-only world mount supplied with that package:

```sh
docker compose -f compose.yaml -f worlds/emberwild/compose.override.yaml up --build
```

Each world has a separate save directory: `data/minimal/` or `data/emberwild/`. Old `data/characters.json` files are left alone. The [migration instructions](docs/DEPLOYMENT.md#existing-emberwild-saves) describe how to adopt old saves deliberately.

## Build your own game

Copy the included example and change its manifest and JSON definitions. No engine changes are required for a new map, quests, items, NPCs or spawns. Follow the [world authoring tutorial](docs/WORLDS.md).

World packs can contain trusted JavaScript modules for specialized geometry, rules and presentation. This alpha's module interfaces are experimental; packs are installed by the operator and must not be accepted as untrusted uploads.

## Develop and verify

With Node.js 22+ on your PATH:

```sh
npm ci
npm test
npm run test:minimal
npm run world:check
npx playwright install firefox
npm run test:browser
```

If using the launcher's local Node, first run `export PATH="$PWD/.tools/node/bin:$PATH"`. The browser smoke test starts its own disposable server and saves. On Linux without working headless WebGL, use `xvfb-run -a env BROWSER=firefox HEADED=1 npm run test:browser` after installing Xvfb and Playwright's browser dependencies. See [contributing](CONTRIBUTING.md).

After installing an Emberwild source checkout, run `npm run build:world-assets` to regenerate and verify all models/thumbnails before `npm run test:emberwild`, which includes generated-export verification alongside its simulation/network checks. Playing the demo itself does not require those exports. Its browser workflows and asset tools are documented in the world package.

## Build release downloads

```sh
npm run package:release
# Also build a separate world download and a convenient combined starter:
npm run package:release -- --world emberwild
```

The `dist/` directory contains versioned `.tar.gz` downloads, per-file release manifests and `SHA256SUMS`. Runtime saves, installed dependencies, Git history, logs and test screenshots are excluded through explicit input lists. Packaging needs the standard `tar` executable. [Release instructions](docs/RELEASING.md) cover verification and distribution choices.

## Current scope

This is a single-process alpha engine for learning, self-hosting and building RPG samples. The included world allows 16 players; Emberwild retains its 64-player cap. Functional capacity checks are not a sustained-load benchmark. The browser-key identity system has no cross-device login or recovery. Progress since the last successful save can be lost on an abrupt failure.

Independent zone workers, transactional database storage, account services, public-service abuse controls and production-scale validation remain future work. [Architecture and scaling](docs/ARCHITECTURE.md) explains the current boundaries; [release status](docs/RELEASE_STATUS.md) lists the remaining alpha preparation.

Original engine and included example code/content are MIT licensed. Each external world carries its own license. Preserve [third-party notices](THIRD_PARTY.md) when redistributing dependencies.

## Live content updates

Operators can add NPCs, mobs/spawns, quests, items and abilities, or update dialogue, announcements and vendor stock while players remain connected. Use validated JSON bundles through the local CLI; accepted changes persist across restarts. See [the live update guide](docs/LIVE_UPDATES.md) and the included Meadow market-day example. Code, geometry, removals and changes to existing gameplay definitions still require maintenance.

## Source-only builds and websites

Only source belongs in Git; generated models, previews, videos and websites are build artifacts. Run `npm run hooks:install` after cloning and `npm run check:source` before committing. CI runs the same guard. `npm run build:world-assets` rebuilds the entire optional Emberwild library, including future/unused content. `npm run build:site` generates this project’s landing page, interactive scenes and recorded demo clips in ignored `.site/`; Emberwild has its own page source and workflow. See [build, release and GitHub Pages setup](docs/BUILD_AND_PAGES.md).
